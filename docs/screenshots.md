# Screenshot review — all 34 original PNGs

Reviewed visually on 22 September 2026. Source: the original project’s `Screenshots` folder. Original files were not changed. The names below preserve the original narrow no-break space before AM/PM.

## Main finding

The screenshots document a **Windows 11 endpoint authentication-monitoring lab using local accounts**, PowerShell, Security events, and Sysmon. They do not demonstrate Active Directory Domain Services, a domain controller, a domain join, organizational units, domain Group Policy, Kerberos, or centralized collection. The strongest story is configuring auditing, generating a controlled account lifecycle, interpreting four Security event IDs, and exporting evidence with hashes.

The public evidence set contains the ten **Keep main** images plus two appendix images showing effective lockout policy and local Users-group membership. Other appendix recommendations remain in the original folder. This selection contains no visible passwords, tokens, personal email addresses, product keys, or non-lab account names. It does contain lab hostnames, lab account names, process paths, GUIDs/logon IDs, timestamps, and hashes. These are useful lab evidence; review any replacement captures before publication. The Windows activation watermark in some originals is unrelated to the security result and is not evidence of a project failure. Do not edit event values, timestamps, or output to improve presentation.

**Keep appendix** means optional background evidence; it need not be included in a concise repository. **Omit** means leave it out of the public portfolio, not delete the original. **Recapture** identifies an image whose purpose is useful but whose current form needs replacement.

The supplied parser chooses a nonzero `SubStatus` first, then falls back to `Status`, and exports this as `StatusCode`. Therefore describe `0xC000006A` as the **parser's normalized diagnostic code**. The screenshots do not expose the raw 4625 `Status` and `SubStatus` fields separately. Do not relabel the displayed value as raw `Status` without obtaining the original event XML.

The 4740 record is timestamped **3 milliseconds before** the last 4625 record. Preserve this order and precision in the table; do not reorder records to match a simplified narrative. Three failures and a lockout are observed in the selected data, but screenshot evidence alone does not establish that no other logon attempts occurred. The later success is approximately 6 minutes 24 seconds after lockout, compatible with the displayed five-minute policy; this does not prove the unlock mechanism.

## Evidence limits to disclose

1. **Local lab, no demonstrated AD deployment.** Local group output explicitly says PrincipalSource Local; events show WORKGROUP and machine-local account domains. Domain-controller and domain-joined-client claims would require a separate extension.
2. **Time accuracy remains open.** Screenshot filenames and guest taskbar clocks often differ by hours; one baseline capture even differs by calendar date. Treat filenames as capture labels and embedded event times as source records. Do not claim verified wall-clock timing or silently correct historical evidence. A future run should record UTC, local offset, Windows Time service state and synchronization source before generating events.
3. **Exact installed Sysmon configuration is unverified.** Image 14 installs `sysmon-lab-clean.xml`, while the provided file is named `sysmon-lab.xml`. Need a configuration hash or captured active configuration to establish that these contents match.
4. **Only Sysmon process creation is demonstrated.** No screenshot verifies Event ID 3 network connections, 11 file creation, or 22 DNS queries. Configuration support for those events is not the same as executed validation.
5. **Filter expression not shown.** Image 32 confirms six displayed results, not the precise account/time/XML filter used. Include a saved custom view XML file and a readable filter screenshot if claiming reproducibility.
6. **Event exports are not available for independent validation.** Keep raw EVTX private, but add sanitized XML or a reviewed machine-readable subset with `EventRecordID`, source computer, UTC timestamp, and separate status fields.
7. **Cleanup and recovery are not demonstrated.** No final screenshot shows account disable/removal, original lockout settings restored, or snapshot rollback verification. Do not state these were completed.
